# עוגן פליי — חנות אפליקציות

אתר Next.js 14 + TypeScript + Tailwind + Framer Motion, עם התחברות/הרשמה דרך Supabase Auth ואחסון קבצים ב-Cloudflare R2.

## מה כלול

- עמוד בית כהה ומונפש עם חנות אפליקציות, חיפוש וסינון לפי קטגוריה.
- הרשמה כמשתמש רגיל (מייל + שם משתמש + סיסמה) עם אימות מייל.
- הרשמה כמפתח, כולל מסך הסכמה לתנאי שימוש (5 אפליקציות / 30MB לחשבון רגיל, 50 אפליקציות / 100MB ל-PRO, בדיקה ידנית, איסור תוכן לא צנוע/לא הולם לפי סטנדרט "נטפרי", חסימה לצמיתות במקרה של הפרה).
- דשבורד מפתח: העלאת אפליקציה עם עורך תיאור עשיר, סטטוס (ממתין/מאושר/נדחה), נקודות, בקשת שדרוג ל-PRO.
- פאנל ניהול (למייל e0556770172@gmail.com בלבד): תור בדיקה עם הורדה לבדיקה, אישור/דחייה/העברה לארכיון/מחיקה, אישור/דחיית בקשות PRO, ניהול משתמשים (חסימה, מינוי לצוות פיקוח, הפיכה למפתח PRO).
- פאנל פיקוח: אותו תור בדיקה עם יכולת אישור/דחייה (ללא מחיקה וללא ניהול משתמשים).
- קבצי אפליקציות ואייקונים מאוחסנים ב-Cloudflare R2, עם קישורי הורדה חתומים (Presigned URLs) שנוצרים בשרת ללא תלות בחבילת AWS SDK (מימוש עצמאי וקליל של AWS Signature V4 עם מודול ה-crypto המובנה של Node — כך שההתקנה קלה ומהירה).

כל פעולות הכתיבה הרגישות (אישור/דחייה, חסימה, ניקוד, מכסות) מתבצעות אך ורק ב-API Routes בשרת עם מפתח ה-service role של Supabase, כדי שאי אפשר יהיה לעקוף אותן מהדפדפן.

## הרצה במחשב האישי

דרישה מקדימה: Node.js גרסה 18 ומעלה (מומלץ 20+). בדקו עם `node -v`.

1. חלצו את הקובץ ה-ZIP ופתחו טרמינל בתיקייה.
2. התקינו את החבילות:

   ```bash
   npm install
   ```

3. קובץ `.env.local` כבר מוכן עם כל המפתחות שסיפקתם (Supabase + R2). בדקו שהערכים נכונים, ובמיוחד ודאו ש-`R2_BUCKET_ASSETS`, `R2_BUCKET_APPS`, ו-`R2_BUCKET_UPLOADS` תואמים בדיוק לשמות הדליים שיצרתם ב-Cloudflare (השמות חייבים להיות מדויקים, כולל אותיות קטנות/מקפים).
4. **חשוב — הרצת סכימת מסד הנתונים:** לא הצלחתי להתחבר לפרויקט ה-Supabase הספציפי שלכם (`ipflzyjbhfqktnjjjsyg`) דרך הכלים שלי — הוא לא הופיע ברשימת הפרויקטים המקושרים. יש להריץ את הסכמה ידנית:
   - היכנסו ל-https://supabase.com/dashboard/project/ipflzyjbhfqktnjjjsyg/sql/new
   - העתיקו את כל התוכן מתוך `supabase/migrations/0001_init.sql` והדביקו שם, ואז לחצו Run.
   - זה ייצור את כל הטבלאות, הטריגרים וההרשאות (RLS), כולל טריגר שהופך אוטומטית כל משתמש שנרשם עם המייל `e0556770172@gmail.com` למנהל.
5. בהגדרות הפרויקט ב-Supabase (Authentication → URL Configuration) הוסיפו לרשימת ה-Redirect URLs:

## מבנה הדליים (Buckets) ב-R2

הקוד מצפה לשלושה דליים, עם השמות המדויקים שתגדירו ב-`.env.local`:
- **assets** — אייקונים של אפליקציות (`R2_BUCKET_ASSETS`)
- **apps** — קבצי האפליקציות עצמם (`R2_BUCKET_APPS`)
- **uploads** — נשאר פנוי לשימושים עתידיים (`R2_BUCKET_UPLOADS`)

אין צורך להפוך את הדליים לציבוריים — כל הגישה (הורדה והעלאה) מתבצעת דרך קישורים חתומים שפגים אחרי כמה דקות.

## פתרון תקלות

### שגיאת "Failed to fetch" בהעלאת אפליקציה (הכי חשוב לתקן!)

ההעלאה בפועל של קובץ האפליקציה מתבצעת ישירות מהדפדפן אל Cloudflare R2 (לא דרך השרת שלנו — כך זה מהיר ולא עמוס שרת). בגלל זה, כל דלי חייב מדיניות **CORS** שמרשה לדפדפן לבצע בקשות `PUT` מהדומיין של האתר שלכם. בלי זה, הדפדפן חוסם את הבקשה ומקבלים בדיוק את השגיאה "Failed to fetch".

**איך מגדירים:**

1. כנסו ל-Cloudflare Dashboard → R2 → לכל אחד משלושת הדליים (`ogen-play-apps`, `ogenplay-assets`, `ogenplay-uploads`) בנפרד.
2. Settings → CORS Policy → Add CORS policy.
3. הדביקו את המדיניות הבאה (עדכנו את הכתובות לפי הצורך):

   ```json
   [
     {
       "AllowedOrigins": [
         "http://localhost:3000",
         "https://your-production-domain.com"
       ],
       "AllowedMethods": ["GET", "PUT", "HEAD", "DELETE"],
       "AllowedHeaders": ["*"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

4. שמרו, וחזרו על הפעולה בשלושת הדליים. **חשוב:** אחרי שהאתר עולה לאוויר (Vercel), יש לחזור לכאן ולהוסיף גם את הכתובת הסופית (`https://ogen-play.vercel.app` וכו') לרשימת ה-`AllowedOrigins` בכל דלי, אחרת ההעלאות וההורדות ייכשלו גם שם.
5. נסו להעלות אפליקציה שוב — השגיאה אמורה להיעלם תוך דקה-שתיים (יש לפעמים השהיה קלה בהפצת ההגדרה).

### כיווניות RTL (עברית הפוכה, אייקונים בצד הלא נכון)

תוקן: העורך העשיר לתיאור אפליקציה קיבל `dir="rtl"`, כל שדות הטופס (התחברות/הרשמה/חיפוש) קיבלו כיווניות RTL מפורשת כדי לעקוף כיווניות LTR שדפדפנים כופים אוטומטית על שדות מסוג email, וסרגל הקטגוריות בדף הבית עבר לצד ימין. אם אחרי `npm install` מחדש (או משיכת הגרסה החדשה) עדיין רואים בעיה דומה — ספרו לי בדיוק היכן, ואתקן.

## פרסום ב-GitHub

```bash
cd ogen-play
git init
git add .
git commit -m "עוגן פליי - גרסה ראשונית"
```

ואז ביצרתם ריפו ריק ב-GitHub, יש לחבר ולדחוף:

```bash
git remote add origin https://github.com/USERNAME/ogen-play.git
git branch -M main
git push -u origin main
```

**שימו לב:** קובץ `.env.local` נמצא ב-`.gitignore` ולא יעלה ל-GitHub — וזה בדיוק הרצוי, כי הוא מכיל מפתחות סודיים.

## פרסום ברשת (Vercel — הכי פשוט לפרויקט Next.js)

1. היכנסו ל-https://vercel.com והתחברו עם חשבון GitHub.
2. New Project → בחרו את הריפו `ogen-play`.
3. במסך ה-Environment Variables, הזינו את **כל** המשתנים שמופיעים בקובץ `.env.example` עם הערכים האמיתיים שלכם (בדיוק כמו ב-`.env.local`), כולל `NEXT_PUBLIC_SITE_URL` שצריך להיות כתובת ה-Vercel הסופית (אפשר לעדכן אחרי הפריסה הראשונה).
4. לחצו Deploy.
5. אחרי שהאתר עלה, חִזרו להגדרות ה-Redirect URLs ב-Supabase והוסיפו את כתובת ה-Vercel (למשל `https://ogen-play.vercel.app/auth/callback`).

## הערות אבטחה חשובות

- שיתפתם את המפתחות (Supabase secret key, R2 access keys) בשיחה הזו בטקסט פשוט. הם נשמרו רק בקובץ `.env.local` המקומי שלכם (לא עולה ל-Git). מומלץ בכל זאת, לפני שהאתר עולה בפועל לאוויר, לגשת ל-Cloudflare R2 וליצור מחדש (Rotate) את מפתח הגישה הסודי, וכן לשקול ליצור Publishable Key חדש ב-Supabase — כדי לוודא שהמפתחות שנחשפו בשיחה לא בשימוש בפרודקשן.
- מפתח ה-service role של Supabase (`SUPABASE_SECRET_KEY`) חייב להישאר אך ורק במשתני סביבה בצד השרת (וכך זה בנוי בקוד) — לעולם לא לחשוף אותו בצד לקוח.
